ColdHook — Background Paths Performance Fix

1 prompt · src/components/ui/background-paths.tsx

Root cause:

FloatingPaths renders 36 motion.path elements and is mounted twice in the hero (position={1} and position={-1}) — 72 simultaneously animating SVG paths total.

The pathOffset and pathLength properties in framer-motion map to stroke-dashoffset and stroke-dasharray. Animating these forces the browser to recalculate the geometric length of each cubic bézier path on every frame — this cannot be GPU-composited and runs entirely on the main thread. With 72 paths all cycling at once, this is the primary source of the page lag.

Fix strategy:
Remove pathLength and pathOffset from the animation entirely. Keep each path drawn at a fixed partial length (set via initial only — no animation). Replace the motion with a simple opacity pulse, which is GPU-compositable. Add will-change: "opacity", stagger starts across paths to spread CPU load, and respect the user's reduced-motion preference. The visual result is nearly identical — semi-transparent curved lines that breathe — with a fraction of the rendering cost.

Both pathLength and pathOffset map to stroke-dasharray / stroke-dashoffset.
Animating these properties forces the browser to re-measure the geometric length
of each SVG cubic bézier path every frame. This measurement cannot be offloaded to
the GPU — it runs on the main thread. With 72 paths animating concurrently
(the component is mounted twice with position=1 and position=-1), this is the
direct cause of the page lag.

opacity, by contrast, is GPU-compositable and has near-zero CPU cost.
